# Tailor-IS 质量保障闭环管理机制

> **文档编号**: QA-PROCESS-001
> **创建日期**: 2026-07-21
> **用途**: 建立可持续的质量跟踪与闭环管理流程

---

## 一、核心理念

```
发现问题 → 记录登记 → 分析定级 → 分配修复 → 验证关闭 → 复盘归档
    ↑                                                          |
    └──────────────── 持续改进循环 ─────────────────────────────┘
```

---

## 二、角色与职责

| 角色 | 职责 | 负责模块 |
|------|------|---------|
| **质量负责人** | 审计计划制定、问题定级、报告审核 | 全项目 |
| **模块负责人** | 问题修复、代码审查、测试验证 | 各微服务模块 |
| **DevOps** | CI/CD 质量门禁、部署校验、监控告警 | 基础设施 |
| **QA 工程师** | 测试用例编写、回归测试、覆盖率跟踪 | 全项目 |
| **前端负责人** | 前端问题修复、类型安全检查、UX 验证 | 前端项目 |

## 三、定期跟踪机制

### 3.1 跟踪节奏

| 周期 | 活动 | 参与人 | 产出 |
|------|------|--------|------|
| **每日** | Pre-commit Hook 自动检查 | 开发者 | 即时反馈 |
| **每周** | 问题修复进度 Review | 模块负责人 | 进度更新 |
| **每两周** | Sprint 质量回顾 | 全团队 | 质量报告 |
| **每月** | 全量自动化审计 | AI 审计系统 | 诊断报告更新 |
| **每季度** | 质量目标达成评估 | 质量负责人 | 季度评估报告 |

| 检查项 | 触发时机 | 工具 | 频率 |
|--------|---------|------|------|
| 密钥硬编码 | git commit | pre-commit.sh | 每次提交 |
| 路由端口合规 | git commit | pre-commit.sh | 每次提交 |
| 异常处理器完整 | git commit | pre-commit.sh | 每次提交 |
| 容器命名规范 | git commit | pre-commit.sh | 每次提交 |
| TypeScript 类型 | git commit | pre-commit.sh | 每次提交 |
| 数据库连接安全 | git commit | pre-commit.sh | 每次提交 |

| 代码质量门禁 | PR 合并 | sonar-quality-gate.yml | 每次 PR |

## 四、问题生命周期管理

### 4.1 状态流转图

```
                    ┌──────────┐
                    │  未处理   │
                    └────┬─────┘
                         │ 分配责任人
                    ┌────▼─────┐
                    │  处理中   │
                    └────┬─────┘
                         │ 提交修复
                    ┌────▼─────┐
                    │  待验证   │───验证不通过───→┌──────────┐
                    └────┬─────┘                  │  重新打开  │
                         │ 验证通过               └────┬─────┘
                    ┌────▼─────┐                       │
                    │  已验证   │←──────────────────────┘
                    └────┬─────┘
                         │ 归档
                    ┌────▼─────┐
                    │  已关闭   │
                    └──────────┘
```

### 4.2 状态变更通知

| 状态变更 | 通知方式 | 通知对象 |
|---------|---------|---------|
| 新建问题 | 文档更新 | 质量负责人 |
| 分配责任人 | 文档更新 | 责任人 |
| 修复完成 | 文档更新 | 验证人 |
| 验证通过 | 文档更新 | 模块负责人 |
| 验证不通过 | 文档更新 + 即时消息 | 修复人 |
| 问题关闭 | 文档更新 | 全团队 |

## 五、质量门禁标准

### 5.1 代码提交门禁

| 检查项 | 通过标准 | 不通过处理 |
|--------|---------|-----------|
| 密钥硬编码 | 无硬编码密钥 | 阻断提交 |
| 路由前缀 | 全部使用 `/api/v1` | 阻断提交 |
| 异常处理器 | 子模块无 Exception.class 兜底 | 阻断提交 |
| 容器命名 | 符合 `tailor-is-xxx` 规范 | 阻断提交 |
| TypeScript | 无 `any` 类型 | 阻断提交 |

### 5.2 PR 合并门禁

| 检查项 | 通过标准 | 不通过处理 |
|--------|---------|-----------|
| 代码审查 | 至少 1 人 Approve | 阻断合并 |
| 单元测试 | 全部通过 | 阻断合并 |
| 覆盖率 | 新增代码覆盖率 > 80% | 警告 |
| 安全扫描 | 无高危漏洞 | 阻断合并 |
| Sonar 质量门 | 无新增 Bug | 阻断合并 |

### 5.3 部署门禁

| 检查项 | 通过标准 | 不通过处理 |
|--------|---------|-----------|
| 环境清理 | 旧容器/卷/网络已清理 | 阻断部署 |
| 中间件健康 | MySQL/Redis/Nacos 全部健康 | 等待就绪 |
| 服务注册 | 全部服务注册到 Nacos | 阻断上线 |
| E2E 测试 | 核心链路测试通过 | 阻断上线 |
| 冒烟测试 | 登录/商品/订单 基础功能正常 | 阻断上线 |
